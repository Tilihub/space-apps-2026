## Verified results with Petros's published example

All seven baseline days are measured for each compared field. The module computes
the following medians from the input, rather than embedding these values in code:

| Crew | Sleep (h) | Resting heart rate (bpm) | Mood | Stress | Fatigue |
| --- | ---: | ---: | ---: | ---: | ---: |
| c1 | 7.8 | 61 | 8 | 3 | 3 |
| c2 | 7.3 | 67 | 7 | 3 | 4 |
| c3 | 7.5 | 65 | 7 | 4 | 3 |
| c4 | 7.8 | 62 | 7 | 3 | 3 |
| c5 | 8 | 58 | 8 | 2 | 3 |

The three paired day-42 scenarios pass through `POST /check-ins` and the
medical officer's `GET /daily` in the canonical dispatcher:

| PET-1 case | Verified result |
| --- | --- |
| c1 usual | `no_changes` |
| c3 missing | `not_enough_data`; resting heart rate and fatigue stay null |
| c4 incident | `changes_found`; all five compared measures changed for three consecutive days |

The crew POST returns only the saved entry and basic Today object. Every crew
token is refused at daily analysis, history and weekly paths. Each case starts
from a fresh temporary context, preserves the baseline and leaves other crew
histories unchanged. No real SQLite session is opened.

## Differences from the accepted stage cases

Compatibility of the file format does not establish compatibility of the stories.
The approved shared contract points to zt's newer `people/zt/demo-cases.md`:

| Crew/context | Current PET-1 example | Accepted stage target |
| --- | --- | --- |
| c4 | Sleep reference 7.8 h; all five measures change in Petros's supplied incident input | Sleep reference 6.8 h; only sleep flagged in the stage input, for three days |
| c3 | Missing pulse and fatigue on day 41; no sustained mood decline | Six-day mood change; pulse gaps on days 39 and 41, without interrupting mood |
| c1 | Resting reference 61 bpm, sleep 7.8 h | Stage ranges 52-55 bpm and 6.6-7.0 h |
| Cabin context in scenarios | Synthetic CO2 warning at day-42 check-in | Potest's separate historical RR-9 replay, recovered by 07:00 |

As an additional check, submitting zt's c4 stage input to the existing PET-1
history does flag only sleep for three days, but reports a **7.8 h** reference.
That is not the required 6.8 h result. The correct fix is an updated source
fixture from Petros, followed by an explicit fresh-store/reset check; changing
the comparison algorithm to manufacture the desired number would be incorrect.
Existing stored baselines stay fixed when the external file is edited.

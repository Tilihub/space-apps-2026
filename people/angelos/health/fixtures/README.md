# PET-1 example input provenance

`stage-health.json` and `stage-scenarios.json` are unchanged copies of Petros's
aligned source files at `1b736f50332423657fb9b5568bb1c1e5e0459f50` (PR #64).
They verify the accepted stage cases without changing the earlier snapshots.
Runtime still reads the canonical file in Petros's folder; these are test inputs.

`health.json` and `scenarios.json` are unchanged copies of the same-named files in
`people/petros_the_space_larper/demo-data/` from commit
`12c840ee2ab9ced49b01a12efb5e5063487de594` on
`petros_the_space_larper/astronaut-health-research`.

It contains fictional daily records for five crew members, explicitly labelled
`kind: synthetic`. It is not a real NASA astronaut dataset or medical guidance.
No observations are generated by the health module. Reference days 29-35 stay
separate from recent days 36-41; the app supplies new days.

This snapshot pins the earlier PET-1 inputs for reproducible tests. The source
package is now on main through PR #51. The accepted contract requires different values from
zt's demo cases (for example c4's 6.8 h reference instead of this file's 7.8 h).
Petros owns that update. The module reads his canonical file on reset when it
exists, otherwise uses this labelled example. Tests pin this example explicitly
so their expected values stay reproducible. No teammate's source file was edited.

The scenarios' medicine and cabin fields are retained only as part of the source
example. Health tests send **only** `checkInBody`; they do not import its synthetic
cabin warning into Potest's historical environment replay or its symptoms into
dadis2's module.
